## Problem and intended behavior

Implementation dependency for cooneycw/skillc#536 item 4, within owner-authorized wave `skillc-complete`. A failed CPP gate leaves resumable state. Skillc currently refuses to attribute a later run whenever that state is nonempty. Comparing start/end filesystem hashes alone would be insufficient: the candidate and its background children can write the state under the same UID, and the witness execution lock does not exclude them.

Expose the exact state bytes the pinned runner actually consumed and generated, together with its existing stage facts, so a consumer can reconcile an honest resumed run with previously witnessed evidence. This does not authenticate an operating-system writer or certify a whole gate merely because two hashes match. It is a prerequisite for the existing item4 acceptance, not a new behavioral study or a request to broaden enrollment.

## Smallest proposed contract, to verify in the implementation plan

Add an optional, versioned `resume_state_evidence` object to the existing single runner-result JSON for run and explicit/automatic resume. Keep persisted state-file schema and resume decisions unchanged. The object identifies the runner family/plan, exact selected consumed bytes, last successfully generated bytes, and final state presence/cleanup. Fields use bounded logical filenames, SHA256 and byte counts, explicit none/loaded/written/unreadable states and fixed safe reasons. No raw state, host paths, command strings, exception text, credentials or authentication claims.

- Compute consumed identity from the actual buffer parsed into the selected state, including automatic `find_latest`; do not reopen the file to claim what was consumed.
- Compute generated identity from the exact serialized byte buffer successfully written; failed/partial writes cannot claim success, and no save is distinct from saving unchanged bytes.
- Keep transient evidence out of persisted `to_dict` so no recursive receipt is created.
- Preserve in-memory terminal stage facts on success and failure. A later filesystem reload must not supply purported runner-owned stage evidence.
- Report cleanup/remaining-state accurately; a removed cache is not an inheritable surviving cache.
- Old consumers may ignore the additive field. Missing/unknown/malformed metadata remains unsupported to new consumers; it never means an observed empty state.

Likely source points are `lib/cicd/state.py` (`load`, automatic `find_latest`, `save`, cleanup) and `lib/cicd/runner.py` (run/resume result construction and failure-path state reload). Revalidate these and exact bundled mirrors on current origin/main before choosing file scope; generated files must come from normal sync tooling.

## Acceptance and controls

1. Commit a concise v1 contract with limits and produce the metadata through real load/save/run/resume paths, without changing ordinary resume behavior.
2. Independent good/bad controls cover explicit and automatic selection, no selected input versus invalid input, exact byte sizes/hashes, failed/partial save, no-op/no-save and successful cleanup.
3. Deterministic timing-swap regressions demonstrate that changing a file after its selected load does not rewrite the consumed identity, and changing it after save does not rewrite the generated identity or terminal stage facts. Prove regressions red on pre-fix code where applicable.
4. Single-document and bounded-field controls reject malformed/unknown/duplicate protocol output at the consuming boundary. The producer contract must permit the skillc follow-up to reject seeded cache, before-load/restored swaps, after-save/export swaps, other repository/attempt/source/plan state, missing stage history, incomplete output and unconfirmed stop.
5. The consumer must reconcile carried stages against prior controller-held attributable stage facts; this producer PR does not claim that the metadata alone establishes inherited success. Same-UID filesystem swaps are in scope of the byte accounting; coordinated replacement of the entire trusted output stream remains an explicit existing trust limit.
6. Preserve stdout/privacy and existing result semantics. Run focused tests, committed controls, full `make verify`, counter-model review and required exact-head CI. No live model calls or deployments are needed.

## Coordination and boundaries

Skillc consumer/protocol support, exact new profile/inventory pins and its four item4 acceptance cases remain in cooneycw/skillc#536 under a revised concrete gate after the producer commit exists. Old pinned profiles remain conservative; no retrospective credit or silent upgrade. Do not modify the already approved/frozen skillc#557 historical18-attempt repeat or its declaration. No issue434 actor re-pin, broad runner-state redesign, host configuration, new paid study or general provenance platform.

The initial planning assumption that matching end snapshots was enough was rejected before implementation. This issue records the concrete cross-repository dependency needed to complete the originally scoped work; implementation still requires the wave orchestrator's fresh Step3 ruling.
