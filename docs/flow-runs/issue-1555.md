Proposed v1 wire contract (fixed closed object)

    resume_state_evidence = {
      "version": 1, "family": "cpp-run-state", "plan": "check",
      "consumed": {"status":"loaded", "file":"check-ab12cd34.json",
        "sha256":"sha256:<64 hex>", "bytes":1234, "reason":null},
      "generated": {"status":"written", "file":"check-ab12cd34.json",
        "sha256":"sha256:<64 hex>", "bytes":1456, "reason":null},
      "final_state": {"status":"present", "reason":null}
    }

- consumed status: none/loaded/unreadable; generated: none/written/unreadable;
  final_state: present/absent/unreadable. Non-data states have null file/hash/bytes
  and a fixed safe reason. Final presence refers only to the selected/generated
  logical leaf, never all files in a directory or authenticated writer identity.
- plan is a 1-64 character alphanumeric/underscore/hyphen logical id; filename
  is a 1-128 character alphanumeric/dot/underscore/hyphen basename starting with
  alphanumeric. No slash, backslash, traversal, control characters or host paths.
  Unsafe values produce null/unreadable metadata, without changing resume choice.
- byte count is a non-bool integer in0..67108864 (64MiB). Oversized state keeps
  existing load/save behavior but protocol evidence is unreadable/size-limit;
  do not silently truncate bytes or hashes. SHA256 is exact lowercase64 hex.
- Reasons are a short fixed enum (no-selected-state, no-save, not-observed,
  selection-unreadable, input-unreadable, parse-failed, serialization-failed,
  write-failed, short-write, cleanup-failed, presence-unreadable, unsafe-logical-id,
  size-limit). No raw state, command text, exception values or arbitrary labels.
- Old consumers may ignore the additive object. A new consumer treats missing,
  unknown-version, malformed, incomplete or contradictory metadata as unsupported,
  never as empty state. Same bytes in another attempt/repository/source/plan do
  not inherit trust. A successful cleanup does not leave a surviving cache lease.

Explicit proposed error-policy ruling (narrow but observable)

Lower load/save/find_latest/runner APIs continue to raise the ORIGINAL exception.
The collector records only errors from its exact I/O/parse/serialization operations
and retains the original exception object privately; swallowed invalid candidates
are not terminal error identities. No blanket catch of arbitrary step failures.

At JSON-mode run_plan/resume_run boundary ONLY, if the propagated exception is
that exact currently tracked state-operation failure, emit one safe failure JSON
and return1 instead of an uncaught traceback/no result. Example before: corrupt
explicit resume or failed save raises JSONDecodeError/OSError, exits1, no runner
result. Proposed after: success=false, fixed error `runner-state-unavailable`,
fixed state_operation enum and unreadable v1 evidence; include frozen stage facts
only if actually available. Omit unknown population/run fields rather than invent
zeros or IDs. That error envelope establishes no successful gate/stage credit.
The existing evidence wrapper still observes/re-raises before this CLI boundary.

No-json mode and direct engine calls re-raise the same original exception;
untracked same-class OSError/ValueError/TypeError from a step/configuration or an
unrelated bug still propagates. Do not serialize exception strings or host paths.
This CLI policy needs root acceptance in this gate; if rejected, report the
resulting wire-coverage gap rather than silently weaken the acceptance.
