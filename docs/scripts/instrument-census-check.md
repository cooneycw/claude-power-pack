# `instrument-census-check` - script reference

Per-script history, indexed from [the scripts inventory](../scripts.md).

## `instrument-census-check`

- instrument-census-check - derives ADR 0008's census MEMBERSHIP from `scripts/` and checks it both ways (#1060): `UNACCOUNTED` is a file named by neither the census nor the exclusions table, `STALE` a subject naming neither a live file nor a declared external subject. #1002 had already made the census COUNT derived, on the grounds that a hand-maintained number is stale from the next append onward; the ROWS stayed hand-appended, so deriving the count made an omission HARDER to see - `65` reads as "the census is current" when it only means "the table has 65 rows". Eight instruments were in neither table when this landed, among them `counter-model-receipt.py`, which then shipped carrying #1047 and #1048, the exact defect class the census exists to bound. It reds on ENUMERATION and never on coverage: an enumerated row with no control stays green, because a gate failing 59 rows on day one is switched off inside a week, which is the oscillation ADR 0009 predicts. The matching rule is the FIRST backticked token of a census row's instrument column - the same rule `scripts-inventory-check` applies to headings, and for the same reason: two looser rules were measured against the real document first, and reading every backticked token anywhere reported 13 unaccounted files of which 7 were false plus 110 non-file subjects bled in from the verdict and consumer columns. The exclusions table reads ALL its tokens, because its first column is a population where a census cell is one subject. The fourteen census subjects with no file under `scripts/` - `ruff`, `mypy`, `pytest`, `gitleaks`, `hadolint`, `make` and the `lib.*` entry points - are declared on an `instrument-census: external-subjects:` marker inside the ADR, a list that narrows and therefore fails loudly. Stdlib-only, git-free and offline, so `make verify` and the slim CI image agree; registered in `controls/instrument-census`, and row 73 of the table it checks, so it accounts for itself
- instrument-census-check typed subjects (#1276) - `make <target>` in a census or exclusions cell is the subject `make:<target>`, not `make`: under the head-word rule every make target collapsed onto one declared external, so a row for a deleted target resolved silently forever. A typed subject is validated as a target the root `Makefile` defines (STALE otherwise, and STALE naming the reason when the Makefile cannot be read). The POPULATION does not widen: only the targets a row names are checked, never every target. `INSTRUMENT_CENSUS_TYPED_SUBJECTS` counts them. `make` left the external-subjects marker because no row reads as bare `make` any more. Committed case `controls/instrument-census/cases/bad-stale-make-target` (a `make nosuch` row) is clean on the pre-#1276 gate and STALE now; `good-accounted` carries a `make verify` row so the typed path is exercised where it must not fire
- instrument-census-check #1268 - rows are the CENSUS TABLES' (`census_rows`: every table whose header is `| # | instrument | verdict ...`, each to its first non-table line; a comment-only line inside a table no longer ends it), so a numbered row in any other table - the Retired table included - cannot join the census. EVERY census table, not the first: kyle's ADR 0005 splits its census into four, and reading only the first gave kyle 24 of 78 rows (measured on this branch before it shipped). A duplicate row number across the census and Retired tables is `DUPLICATE_ROW`. RULING R2: a `### Retired, with the issue that retired it` table - a retired row keeps its number (never reused), may name an absent file (not STALE), is `RETIRED_LIVE` if it names a live one, and is outside the denominator. Rows 32 (`project-next-vendor.py --upstream`, #1069) and 45 (`hadolint`, #943) moved into it, replacing the gap comment, the numbering gaps and the retirement paragraph. The table is the one under its section with the `| # | instrument | retired by |` header: no section is `absent`, a section with no such table is `RETIRED_UNREAD` (a finding - not zero retirements)
- instrument-census-check #1671 - the census is DATA at `controls/census.md`; ADR 0008 keeps the rule and carries no table. `resolve_adr` (still the one resolver all three readers share) tries the data file, then the decision record, then another repository's single matching record, so kyle's in-record census resolves unchanged. A data file WINS OUTRIGHT: a table left in the record beside it is not read. A record emptied of its table with no data file parses to 0 rows and refuses as unread. `controls/instrument-census` gained `bad-unaccounted-data-home` (a leftover record table accounts for the script the data file omits; the pre-#1671 gate scores it clean) and `good-accounted-data-home` (a table-free record; the pre-#1671 gate refuses it), and its constructed anchor resolves the same way.
- instrument-census-check typed `lib.<pkg>` subjects (#1394), the same shape #1276 gave `make:<target>` - a `lib.<pkg>` census subject (row 61, `lib.security gate`) is now validated STRUCTURALLY, against a real `lib/<pkg>/` directory, rather than requiring it stay declared an external subject forever. `lib_subject_problem` is the typed check, read in the main population loop right after the `externals` branch: a subject still DECLARED external (every OTHER `lib.*` row - the kind exists for them too, but nothing registers a marker yet) resolves there first and never reaches it, so this is additive, not a replacement. `lib.security` left the `external-subjects` marker because it now has a real registered `lib-module` control (`controls/lib-security-gate`, see check-negative-controls); row 60 (`lib.security scan`/`quick`/`deep`) shares that one subject and resolves the same way. `INSTRUMENT_CENSUS_TYPED_SUBJECTS` counts `lib.<pkg>` subjects alongside `make:` ones. A row naming a package that does not exist is `STALE`, exactly like a row naming a deleted Makefile target
