# `codex-skill-resync` - script reference

Per-script history, indexed from [the scripts inventory](../scripts.md).

## `codex-skill-resync` (#1136)

- codex-skill-resync - decides whether the generated Codex mirrors need regenerating by ASKING `codex-skill-sync.py --check` what actually drifted, names it, and re-syncs (#1136). Contract `CODEX_RESYNC: current|resynced|unavailable|error`, exits 0/3/0/2. It replaced THREE inline copies of `git diff --name-only ORIG_HEAD..HEAD | grep -q '^\.claude/commands/.*\.md$'` - at `flow/auto.md` Step 6 and Step 7 and at `flow/finish.md` - whose premise was that the generated surface changes only when a COMMAND DOCUMENT changes. It does not: the skills bundle repository docs too, so a bundled-doc edit drifts the mirror while touching no command document and the grep stayed silent. Measured twice in two hours on 2026-09-20, by two sessions on two documents (`docs/decisions/0008-...md` under #1126, `docs/agents/issue-contract.md` under #1133), each costing a full lint-plus-5,100-test gate cycle and a re-gate. A guard that is silent and a guard with nothing to do produce identical output
- codex-skill-resync THE FIX IS NOT A WIDER GLOB - that is a hardcoded universe one entry longer, and the next bundled path would find it blind again. `--check` compares the ACTUAL generated output against the ACTUAL sources using the same generator `--write` uses, so it answers the question rather than predicting it. Cost measured: 0.11s clean, against the 0.00s grep that cost two gate cycles. Nor is it three better copies: three copies of one condition is how the same wrong condition reached three places, so the sites now invoke ONE helper bare (#581) and `tests/test_codex_skill_resync.py` carries a TRIPWIRE that fails if a path-pattern condition reappears anywhere under `.claude/commands/`. That tripwire reads NON-COMMENT lines only - `auto.md` now quotes the old condition in a comment explaining its removal, and a scan matching that would fail on the documentation written to prevent the bug
- codex-skill-resync REPORTS BEFORE IT REPAIRS, and unconditional `--write` was considered and rejected (#1136 ruling). It is idempotent and costs 0.12s, and a guard that does not exist cannot be blind - a real argument. What it loses is the reason the blindness survived: silent repair makes drift never matter, therefore never noticed. Regenerated mirrors would land in an author's commit as a diff they neither made nor read, exactly when the generator's scope has changed and nobody is positioned to see it; and the sync script's SCOPE becomes unobservable - an author never learns that editing `docs/agents/issue-contract.md` reached five Codex skills
- codex-skill-resync `resynced` CARRIES ITS OWN NON-ZERO EXIT (3) and the two house rules point opposite ways: #674 says a new verdict must never become a new exit code, #1027 says each verdict needs its own. #1027 wins because this verdict is read as evidence - it is an ADR 0008 census instrument and its control must tell "found drift" from "found none" by exit code, the only channel that framework scores. The #674 hazard is answered at the call sites, which invoke it bare inside blocks that set no `-e`. `current` and `unavailable` do share exit 0: both mean "nothing to do", the only thing a caller branches on, and the contract line separates them for a reader
- codex-skill-resync CONTROLLED (`controls/codex-skill-resync/`, ADR 0008) - two committed cases, each carrying BOTH inputs: a `stub-sync.sh` standing in for what the generator reports, and a `changed-paths.txt` holding the list the old condition consumed. The gate reads only the first and the anchor only the second, which is the defect and its fix side by side. The anchor is SYNTHETIC because the blind condition never lived in a file - it was three inline shell lines in markdown - so it is lifted into an executable unchanged in substance, reading its path list from a file rather than from real `git diff` so its verdict cannot depend on ambient repository state
