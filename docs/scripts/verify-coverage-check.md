# `verify-coverage-check` - script reference

Per-script history, indexed from [the scripts inventory](../scripts.md).

## `verify-coverage-check`

- verify-coverage-check - accounts for every checker the repository owns and makes `make verify` state what it skipped (#1028). Four checkers were found at once with no path from a change to a verdict anyone consumes, and the shared remedy was not four wirings but answering, mechanically, the question a green from `verify` silently begs: what did it NOT run? It derives two populations from the tree - every `Makefile` target, and every file in `scripts/` - and refuses to let either go unaccounted. Target classes are DECLARED beside the target on a `## verify-coverage: <gate|excluded|utility> <target> - <reason>` directive and then CHECKED against the real prerequisite graph in both directions, which is the one failure ADR 0008's census row 40 names for `make verify` itself and no member row can self-report: a sub-gate silently dropped from the list. Script classes are DERIVED wherever the tree can answer (`gate`/`excluded` by which target invokes it, `ci` by a `.woodpecker.yml` step) and declared in `.claude/verify-coverage.json` only where it cannot - `tested` (a module under `tests/` drives it, so `make test` exercises it), `runtime` (a command or hook reads it), `not-a-checker`. THE SCRIPT POPULATION IS THE MECHANISM FOR NEW CHECKERS, not the target one: 56 of 90 scripts have no Makefile target, so a target-only framework would be satisfied by exactly the checkers it exists to catch - `check-negative-controls.py` was one of them until #1028 gave it one, and it is one of that issue's own four subjects. Two hiding places are closed rather than trusted - a `utility` target whose recipe runs a checking flag or subcommand is refused outright, and `not-a-checker`, the one class the closing report never mentions, is cross-checked against ADR 0008's census with the extraction rule IMPORTED from `instrument-census-check.py` rather than re-implemented, so the two documents have to agree. `--report` prints the closing summary `make verify` ends on. It reads only a step's COMMANDS, never its comments: the first cut grepped the whole pipeline and reported four scripts as CI-covered that the comments merely discuss, which is the wrong direction for this gate to be wrong in. Stdlib-only, git-free and offline, so `make verify` and the slim CI image agree; registered in `controls/verify-coverage`
