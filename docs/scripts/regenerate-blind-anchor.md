Per-script history, indexed from [the scripts inventory](../scripts.md).

## `regenerate-blind-anchor` (#1492)

- regenerate-blind-anchor - regenerates one constructed anchor from its gate's CURRENT code plus a stored unified `.patch` file holding ONLY the anchor's intentional transformation (the blinding, plus whatever path/environment adaptation the anchor's location under `controls/<name>/anchors/` requires) - never the gate verbatim. A mechanical "copy the gate" regeneration drops the adaptation silently (#1182's incident: the regenerated anchor crashed on the known-bad input instead of missing it). The anchor's own hand-written module docstring is preserved verbatim across every regeneration; only the CODE after it is replaced. Default mode reports `matches`/`drift` against the committed anchor (a human-read advisory, never consumed automatically - `make regenerate-blind-anchor-check CONTROL=<name>`); `--write` (`make regenerate-blind-anchor CONTROL=<name>`) overwrites the anchor. Regenerating also resyncs any OTHER drift the gate has picked up since the anchor was last touched - deliberately: that is the defect this tool exists to fix, not a side effect to avoid, as long as the stored patch itself never encodes that drift as intentional. First used for `controls/host-surface-observe/anchors/constructed-blind-covered-by.py`, whose own `.patch` holds exactly two hunks (the `covered_by` blinding, and `REPO_ROOT`'s `parents[1]` -> `parents[3]` depth adaptation). Every regeneration is verified against `check-negative-controls.py --strict` on the owning control, confirming the anchor still misses every known-bad case after resync.
