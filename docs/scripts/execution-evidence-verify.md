## `execution-evidence-verify` (#1366)

- execution-evidence-verify READS THE DURABLE RECORD `/flow:check` LEAVES BEHIND. The runner's own state file (`<git-dir>/cpp-runs/<id>.json` in a git repository since issue #1409, `.claude/runs/<id>.json` otherwise) is a RESUME file that `RunState.cleanup()` deletes on success, so a green `/flow:check` left nothing but the agent's own table. With `CPP_EXECUTION_EVIDENCE=<skill>` set, `lib.cicd.evidence` writes a non-terminal begin record and then exactly one terminal record (completed, failed or interrupted) to `<git-common-dir>/cpp-evidence/<skill>/<invocation>.json` - atomically, outside the working tree, surviving worktree removal, newest 50 kept. It binds repository (credentials stripped from the origin URL), worktree, HEAD, dirty flag and the #804 content signature at start and end, a fresh invocation id plus the runner's run id, the /flow plan-record run id when one exists, the helper's CPP commit and module digests, and per check: observed status, exit (None when the command never ran, never a fabricated 0), timestamps, measured population (`measured: false` stays unmeasured, never 0), skip/not-run reason and output DIGESTS - never raw output or the environment. `declared` (skill, source, parent invocation - from the environment, unverified) is kept apart from `observed`. This reader prints the exact claim a record supports, or each reason it supports none: `supported` 0, `not-supported` 3, `unknown` 4. A local writable record is inspectable evidence, not attestation. Contract and reader example: docs/agents/execution-evidence.md. Red cases: `controls/execution-evidence-verify` (stale same-file re-edit, replayed name, completed-over-unrun-gate; constructed anchor misses all three) and `tests/test_execution_evidence.py` (missing terminal, interrupted, stopped aggregate, zero population, unreadable, unknown schema, privacy with synthetic credentials)
