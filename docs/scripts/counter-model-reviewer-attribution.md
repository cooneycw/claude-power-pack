## `counter-model-reviewer-attribution` (#1048)

- `counter-model-reviewer-attribution` ATTRIBUTES A LANDED RECEIPT TO THE ROLLOUT THAT PRODUCED IT, using the association real receipts actually carry: a receipt records `branch`, and a Codex rollout records its own `cwd` - the per-issue worktree, named for that branch - plus a start timestamp. This is what falsified the `structurally impossible` premise recorded one section above, which had blocked the disposition of the 13 landed `codex/gpt-5.5` receipts since #1091
- `counter-model-reviewer-attribution` IS AN INFERENCE, NOT AN IDENTITY, and the distinction is the point. The WRITER's derivation (#1059) anchors on a thread_id and is an identity; this anchors on a directory name and a time window. Its error rate is MEASURED rather than assumed: against the 16 post-#1059 receipts whose reviewers were independently derived, it agrees with 15, disagrees with 0, and cannot link 1. That control is inside its own output as `agreed=`, not a separate claim
- `counter-model-reviewer-attribution` REFUSES TO REPORT WHEN ITS EXTRACTOR CANNOT DISCRIMINATE. `extractor_distinct <= 1` downgrades any finding to `ATTRIBUTION-UNKNOWN`: with one model value across every rollout, a correct reading and an echoed constant produce identical output, and echoing a constant is the exact defect the 13 receipts are an instance of. The committed pair `bad-disagreement` / `bad-blind-extractor` supplies the SAME disagreement and differs only in that population, so the two verdicts must differ
- `counter-model-reviewer-attribution` A BRANCH NAME IS NOT A REPOSITORY BOUNDARY. The sessions directory spans every repository on the host, so `<another-repo>-issue-9001-alpha` ends with the same branch as ours; matching on the suffix let a neighbour's rollout supply a confident attribution, or manufacture a disagreement, for a receipt it had nothing to do with (counter-model review, #1048 - the detector contract's second question, answered no). The worktree basename must now equal `<repo>-<branch>` exactly, the repository is derived from git's COMMON dir (never the checkout basename, which inside a flow worktree is `<repo>-issue-<n>-<slug>`), and a scan that can establish neither it nor `--repo-name` REFUSES rather than falling back to the loose match. Tightening it did not move the real result - 28 links, 13 disagreements, before and after
- `counter-model-reviewer-attribution` AN AMBIGUOUS LINK IS VERIFIED NEITHER WAY, and an UNREADABLE candidate is ambiguous rather than absent: dropping a linked rollout that declares no model made the remaining ones look unanimous, so a receipt whose real reviewer might be the unreadable rollout was reported as a confident agreement (counter-model review, #1048). Two rollouts in one worktree window recording different models determine nothing; resolving by proximity or recency would manufacture a specific answer out of an unresolved one. `ambiguous=` is counted and reported separately from `unlinked=`
- `counter-model-reviewer-attribution` IS READ-ONLY TO `docs/measurements/counter-model/` and always will be. The owner's disposition (#1048) is ANNOTATE, DO NOT REWRITE: each receipt records what its run believed, which is the evidence of how a documented literal propagated across thirteen runs, and a corpus rewritten to look correct would destroy exactly that
- `counter-model-reviewer-attribution` ITS INPUT HAS A SHELF LIFE - `~/.codex/sessions` is host-local and pruned, so `linked` falls as rollouts age out and a later `unlinked` is not a finding. `docs/measurements/counter-model-reviewer-attribution.md` is the durable record precisely because the input is not
