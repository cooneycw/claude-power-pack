# `mutation-probe` - script reference

Per-script history, indexed from [the scripts inventory](../scripts.md).

## `mutation-probe` (#970)

- mutation-probe - breaks each DECLARED protection of an instrument in turn and requires its control battery to go red (#970). ADR 0008's committed-control bound is necessary and NOT sufficient: an instrument is a STACK of protections and one end-to-end case only travels the path its own input takes, so every OTHER protection can be deleted with the battery still green. Demonstrated in wave `cpp-completion` on 2026-09-15 - nine committed controls, a genuine RED, a GREEN positive control, an orchestrator who read the set and called the positive control load-bearing, and then four protections disabled one at a time with all nine controls still passing, exit 0 every time. A decorative battery and a sound one produce identical output and look identical on the page, so the method that separates them cannot be reading
- mutation-probe verdicts - `CAUGHT` (protection removed, battery red); `UNCAUGHT` (protection removed, battery green - the decorative finding); `ACCEPTED` (declared `expect: "uncaught"` with a written `why`, a gap that is stated rather than hidden); `STALE` (an ACCEPTED gap that is now caught, so the acceptance has outlived its reason - the direction that stops the acceptance field being a one-way fail-open); `INAPPLICABLE` (the edit matched a different number of times than declared, or left the file unparseable, so no weaker instrument was ever produced - presents identically to UNCAUGHT and needs the opposite response); `UNRESOLVED` (the sandbox, gate or battery could not run, or the UNMUTATED battery was already red, against which any mutation reads CAUGHT for free). `--strict` exits non-zero on everything but `CAUGHT` and `ACCEPTED`
- mutation-probe never mutates the working tree. Each run builds a DISPOSABLE SANDBOX - `git ls-files` copied into a temp directory, then `git init` plus one commit so batteries that ask git a question still get an answer - and every mutation is written there. An in-place mutate-and-restore was the first design and is rejected: a kill between the two steps leaves a weakened instrument in the tree, a concurrent suite reads a file mutated for reasons it cannot see, and the restore is the step most likely to be skipped on the failure path. 1,365 tracked files copy in well under a second. `tests/test_mutation_probe.py` asserts the real gate file is byte-identical (sha256) across a probe run
- mutation-probe refuses a mutation that leaves the gate UNPARSEABLE, and the refusal is load-bearing rather than tidy. Without it the cheapest route to a certified battery is a mutation that deletes the file: everything goes red, every mutation reads CAUGHT, and the battery is proven by an edit that never produced an instrument. A mutation must leave something that still RUNS and is merely WEAKER
- mutation-probe declarations live in the battery's own `control.json` beside its cases, never in a separate document - the same rule that keeps the registration directive inside the gate file. `mutations[]` entries are `{name, protection, find, replace, count, expect?, why?}`: `find` is a regex matched with `re.MULTILINE`, `replace` is a LITERAL string and never a substitution template (as a template a backslash is an escape, so swapping one regex constant for another raised `bad escape` and the mutation was scored INAPPLICABLE for a reason unrelated to the gate), and `count` is the number of substitutions that MUST occur - an anchor matching twice is as wrong as one matching nothing. A manifest outside `controls/` declares its own `battery` argv and `battery_cwd`; `{root}` substitutes the sandbox and `{python}` this probe's interpreter, which a battery needing the project's dependencies must use because the sandbox holds tracked files only and therefore has no virtualenv for a runner-resolution walk to find
- mutation-probe does NOT enumerate a gate's protections - a person reads the gate and writes them down. A tool deriving them would be answering "what does this code protect against", which is not a mechanical question, and a derived list that silently under-enumerated would recreate the false completeness the probe exists to find. So the declared count states how hard somebody looked, never what fraction of the gate is covered, and the summary line says exactly that
- mutation-probe discovery is `controls/*/control.json` and deliberately goes no further. A research prototype's manifest is probed by NAMING it with `--manifest`, so a directory of committed fixtures - the probe's own case trees among them - cannot enter the population of the run examining them
- mutation-probe snapshot loses a tracked SYMLINK (#959) - the sandbox is built two ways and both mishandled one, in opposite directions. The GIT lane tested `src.is_file()`, which FOLLOWS the link, so a DANGLING symlink answered False and the path was skipped SILENTLY: the snapshot was missing a control's fixtures and the probe still reported `ok` - the "a partial copy still runs and produces verdicts about a tree missing files nobody named" failure its own OSError branch refuses, arriving through the branch that does not raise. The WHOLESALE lane used `copytree` with the default `symlinks=False`, which DEREFERENCES: ENOENT, step dead. That second lane is the one CI runs, because git is absent from the image by design, so the dev box cannot reach it - found only after the push (Woodpecker pipeline 2220). Surfaced by `controls/flow-vantage`, which commits three dangling symlinks deliberately: `readlink /proc/self/ns/pid` returns `pid:[4026531836]`, a string that is not a path, so the only faithful stand-in for that read is a symlink carrying that target. Both lanes now preserve the link; `tests/test_mutation_probe.py::test_the_snapshot_preserves_a_tracked_dangling_symlink` drives both and fails on the pre-fix code in both
- mutation-probe applied ONE mutation at a time, so two protections that cover for each other both read UNCAUGHT and the method could only ever report "nobody tried removing both", never "genuinely redundant" (#1268 ruling R3). #1396 closes that: a manifest may declare `combinations[]`, naming two or more EXISTING `mutations` entries by name and applying them together in one sandbox, in declared order - each member's `find` is checked against the text AFTER the earlier members' edits, never the original, so a combination whose later step only matches once an earlier one has landed is exactly what "together" means, and one that still doesn't match is INAPPLICABLE rather than silently partial. Retrofitted onto its own motivating case: `shellcheck-gate`'s `zero-matched-is-unknown` / `linter-crash-is-unknown` pair, previously each ACCEPTED on the strength of the other, now has a committed `zero-matched-and-crash-together` combination - MEASURED CAUGHT against the CI-pinned shellcheck v0.10.0 (removing both together makes `cases/unknown-zero-matched` observe a confident clean pass, which `check-negative-controls` reports BLIND), so the pair is real, load-bearing redundancy rather than an accepted gap. A combination's `name` must not collide with any mutation's name, and `check-negative-controls.py`'s own closed `CONTROL_KEYS` schema (issue #1268 R4) was widened to admit the new top-level `combinations` key, a separate mechanism from mutation-probe's own read of it
- mutation-probe's `expect: "uncaught"` entries now also REQUIRE `blocked_by`, a closed-vocabulary category alongside the free-prose `why` (#1396): missing or unrecognized is INAPPLICABLE, naming the enum. `why` stays the human account specific to one gap; `blocked_by` is what makes the reason countable and diffable across the whole registry - most of the pre-#1396 entries' `why` prose, read verbatim, sorted into the same handful of shapes, which became the vocabulary rather than an invented one: `input-cannot-be-committed`, `case-precondition-refused`, `host-or-tool-property`, `masked-by-sibling`, and `anchor-would-also-catch` (a committed case would ALSO be caught by an unrelated check, so it can't isolate the protection under test - a genuinely different shape from the other four, kept separate rather than stretched to fit one of them). Every existing `expect: "uncaught"` entry across `controls/*/control.json` was backfilled in the same change; `make negative-controls` showed zero verdict changes outside the one combination above
