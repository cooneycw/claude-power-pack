# `install-drift` - script reference

Per-script history, indexed from [the scripts inventory](../scripts.md).

## `install-drift`

- install-drift - three-job, read-only host check (#622/#662/#823/#828): it byte-compares installed `~/.claude/scripts/` files with same-basename files in the checkout (not `.sh`-restricted since #828's symmetry fix, ignoring host-owned scripts), preserving the helpers-vs-checkout drift guard through #663's canonical symlink restoration - and, added by #828, it also shells out to `flow-helpers-install.sh --check` (read-only, provably so) to catch a checkout helper that is not installed AT ALL, invisible to a loop that only ever iterates the installed side; only names in that script's own `HELPERS` array (its documented stable-path install set, 21 entries - 20 `.sh` + `flow-wave-plan.py`) are judged missing, reusing that canonical membership rather than duplicating it, and `helpers_missing_checked` distinguishes "the installer is absent or its output is unparseable" from "checked, zero missing" so a subprocess format change can never misreport as clean; the stale/current loop's glob was widened from `*.sh` to `*` in the same PR so `flow-wave-plan.py` - the array's one non-`.sh` entry, and the file a membership-count reconcile surfaced - is judged for content drift too, not only presence; it names CPP marketplace cache families/clone state retired by #662 / ADR 0005 and points at `/plugin uninstall <family>@cpp`; and, added by #823, it directory-diffs installed `~/.codex/skills/<pkg>/` COPIES (made by `codex-skill-sync.py --install`, not refreshed by `git pull`) against the same package under `<checkout>/codex/skills/` - only CPP-owned packages, keyed by "does the installed SKILL.md still carry the GENERATED marker" rather than a dotted-name convention, which is what actually keeps Codex CLI's own `.system/` built-ins (skill-installer, plugin-creator, openai-docs, skill-creator, imagegen, review-agent) out of judgment and separates a genuine orphan (a package this repo used to ship, since deleted, never pruned from the install tree) from a host-owned package that was never ours. An absent or empty install tree reports `codex_skills_checked: false` rather than ever reading as clean. Stale or missing helpers, or stale Codex skills, produce `INSTALL_DRIFT: drift`; migration-only retired-marketplace state and orphaned-but-current Codex skills both remain informational `skipped` (the remedy for an orphan is a prune, not a re-install, so it is never folded into `drift`); `--quiet` emits one non-blocking advisory line per applicable condition, joined, and all check verdicts exit 0. The old clone/cache parity walk has no source after `plugins/` removal. `make install-drift-check` remains wired into the SessionStart reminder and `/cpp:update` Step 7.10. Deliberately not in `make verify`: it inspects HOME, and a CI container legitimately has no install
- install-drift gained a FOURTH root and a provenance line in #1029. (4) `~/.claude/skills/` was uncovered while `~/.codex/skills/` was covered, and the asymmetry was the tell - the script already implemented the right comparison for one root and was simply not pointed at the other. That root is USER-SCOPE, so its packages load in EVERY project; it holds real directories rather than symlinks; and `~/.claude` is not a git repository, so there was no diff, no history and no manifest for them anywhere on the host. Ownership is BY MARKER and the NAME IS NOT THE MARKER: `~/.claude/skills/boot` on the reference host is a different project's skill colliding by name with CPP's `.claude/skills/boot`, and a name-keyed comparison would report it stale forever and teach everyone to ignore the job. The job DELEGATES to `skills-check.py --root <checkout> --managed-root <install root>`, which already owns the `metadata.source` rule and resolves the canonical package FROM the marker rather than from the directory name; only its `MANAGED_*` lines are read, and the same membership floor applies - no recognisable managed-install note reads as `unavailable`, never as clean. (5) Every verdict is now prefixed by `toolchain-provenance`, because all four jobs compare an installed copy against THE CHECKOUT and none of them could say how current the checkout is - a helper that byte-matches a 21-commit-stale checkout is `current` by this script's measure and stale by the only one that matters. Advisory: it changes no verdict, and its line is emitted in `--quiet` OUTSIDE the joined clause list so a repo with no install drift cannot suppress it
- install-drift GENERATES ITS CODEX EXPECTATION (#1670). The Codex arm used to diff installed skills against `<checkout>/codex/skills/`; that tree is ignored build output now, so it would compare against yesterday's build or call every skill orphaned against an empty one. It runs the checkout's `codex-skill-sync.py --write --output-root <tmp>` and compares against that, only when a CPP-generated skill is installed (the build costs about a second at session start). When the expectation cannot be built - no python3, no generator, a failing generator - the skills are UNEXAMINED: their own count (`codex_skills_unexamined`, with `codex_skills_expectation` naming why), never `current` or `orphaned`, and the verdict cannot be `ok`.
