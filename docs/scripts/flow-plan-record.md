# `flow-plan-record` - script reference

Per-script history, indexed from [the scripts inventory](../scripts.md).

## `flow-plan-record`

- flow-plan-record - the `/flow:auto` plan record and as-read issue snapshot, as one helper (#1211): `reconcile` (Step 1: restore the last COMMITTED record from HEAD or remove scratch, #1080), `read-issue` (Step 1: store the body as read, with digest and read time, in the git dir, #1081), `approve` (Step 4: write `docs/flow-runs/issue-<N>.as-read.md` and stamp the record's digest as the Step-6 baseline, #1081/#1082), `drift` (Step 6: `ISSUE_DRIFT: clean|drift|unresolved`), `compliance` (Step 6: `PLAN_COMPLIANCE` + `PLAN_RECORD_STABILITY`, reports and never blocks, #1082) and `head-check` (Step 6: `FLOW_PLAN_RECORD: present|absent|unverified`, the STOP when the record did not ship, #1080). Exits 0 ok / 1 error or absent / 2 usage / 3 finding / 4 unknown, so no cannot-answer state shares a code with clean. `--body-file`, `--live-file` and `--head` replace only the `gh` call so tests drive the real entry point without stubbing `gh`. It replaced roughly 5,700 words of pasted programs and prose in `auto.md`; the reasoning moved to `docs/agents/flow-plan-record.md`, which the procedure links as background rather than required reading
- flow-plan-record lanes check (#1731) - `approve` refuses a record whose run section has no `### Lanes for this change` table, or leaves a lane listed in `.claude/lanes.md` without one of the four answers, through the existing `FLOW_PLAN_RECORD: error - ...` line and exit 1, before anything is written. Three plans had been approved without the table in the first afternoon of the rule and one merged that way. Silent and byte-identical where the project has no lane file. An unusable lane file is `unknown` and refuses; it never reads as no lanes. `Lanes: none - <reason>` is accepted and announced on stderr. The stability digest is untouched (its code is identical to the helper before the change, which a test asserts): what a run demonstrated goes in `docs/flow-runs/issue-<N>.lanes-demonstrated.md`, a file of its own, and `compliance` names on stderr each `will test` lane with no row there, without changing its verdict. An earlier cut kept those rows in the record and exempted them from the digest; three review passes each found a way to hide a plan edit in the exempt part, so nothing is exempt. The helper reads the lane file itself (the Codex `flow-auto` bundle ships it without `lane-file.py`). Committed cases: `controls/flow-plan-record-lanes`, whose blind anchor is the helper at `6b6cc29e`. Background in [the plan-record reference](../agents/flow-plan-record.md)
- flow-plan-record lanes on the verdict line (#1767) - `compliance` puts `, LANES NOT DEMONSTRATED (<lanes>)` or `, LANES NOT CHECKED (<why>)` directly after the `PLAN_COMPLIANCE` verdict word when a lane the plan answered `will test` has no row in `docs/flow-runs/issue-<N>.lanes-demonstrated.md`, or the lane file or that file cannot be read. One function, `lanes_at_close`, decides one of four states (nothing owed, all shown, missing, not checked) before any verdict is printed; the clause and the stderr note are both generated from it. Exit codes are unchanged and the line is byte-identical where nothing is owed (no lane file, a waived plan, no `will test` answer). The stderr note says what to do in each state and is where `/flow:auto` Step 6 sends a run. Where a lane result is owed, the demonstrated file is excluded from the touched files, like the plan record and the as-read snapshot (anywhere else a file at that path is an ordinary touched file, as before): counted, it turned `agreement` into `divergence` for every run that wrote it, a defect of #1731. Committed cases: `controls/flow-plan-record-lanes-verdict`.
