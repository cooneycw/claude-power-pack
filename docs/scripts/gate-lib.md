# `gate-lib` - script reference

Per-script history, indexed from [the scripts inventory](../scripts.md).

## `gate-lib` (#1126)

- gate-lib - the argument and verdict conventions, in one place (#1126, first slice of the #1061 wave). Sourced, not run: `gate_map` declares THIS gate's verdict-to-exit mapping, `gate_arg_value` parses one value-taking flag, `gate_emit` formats the contract line, `gate_exit` exits per the map. The one rule `gate_map` enforces is that EXACTLY ONE verdict maps to exit 0 - which is "an unknowable answer is never rendered as a clean one" (#1014, #800) expressed in exit codes, and derived rather than a hardcoded list of unknown-ish words, because a list goes stale the first time a gate invents a sixth name for the third state. It deliberately does NOT unify the exit codes: `shellcheck-gate.sh` and `npm-global-upgrade.sh` use 2 for unknown and `flow-driver-retirement-check.sh` uses 3, consumers read those numbers today, and #1014's hard constraint is that a shared vocabulary for the third state must let each consumer keep its own policy
- gate-lib exists because the convention was copied rather than shared. Measured on `778ad82`: ZERO shell scripts in this repository source a sibling, 13 files carry `shift 2` across 56 occurrences, and one rule - "a value-taking flag given as the final argument must not be silently empty" - is written five different ways (`${2:?msg}`, `${2:-}` plus `|| die_usage`, `shift 2 || shift`, an explicit `[ $# -ge 2 ]`, and a `require_value` helper). #992 was ONE defect found six times and fixed six times
- gate-lib REFUSES BY EXITING, and that is the design rather than a style choice. `gate_arg_value` sets `GATE_VALUE` in the caller's shell instead of printing a value for `$( )` to capture: a command substitution runs in a SUBSHELL, so an `exit` inside one does not stop the caller and the refusal would be discarded by anyone who forgot `|| exit $?` - which is exactly what the five hand-written idioms depend on an author remembering
- gate-lib is POSIX sh and uses no `local`, because `shellcheck -s sh` rejects it and the first migration target (`shellcheck-gate.sh`, #1127) runs in `koalaman/shellcheck-alpine`, which has NO bash. A bash-only module would work on a dev box and be unsourceable in the image where that gate actually runs
- gate-lib lives at TOP LEVEL rather than `scripts/lib/`, and the reason is measured. Against a fixture tree holding `scripts/shellcheck-gate.sh` and `scripts/lib/gate.sh`, `instrument-census-check.py` reported `INSTRUMENT_CENSUS_EXAMINED: 1` and `scripts-inventory-check.py` reported `SCRIPTS_INVENTORY_EXAMINED: 1` AND EXITED OK - two shell files present, one examined, a green from a blind instrument. Both enumerate with `scripts_dir.iterdir()` filtered on `path.is_file()`, so a subdirectory is skipped whole. `check-negative-controls.py` is the third reader and states the same scope in its `DISCOVERY_SCOPE` constant, with `tests/test_negative_controls.py` pinning it. Widening one reader without the others would split the numerator's population from the denominator's, which is the defect this line of work is about
- gate-lib dispatches its `--check` self-check on a SENTINEL COMMENT the file carries, never on `$0` or `$1`. POSIX `.` passes the caller's positional parameters straight through, so `$1` belongs to whoever sourced it; and `$0` names the CALLER when sourced, so a basename test would also stop the vendored ANCHOR - which has a different filename by construction - from dispatching at all, leaving it to exit 0 on every case and pass the anchor checks for entirely the wrong reason. A vacuous anchor is worse than no anchor, because it reads as a demonstration
- gate-lib control (`controls/gate-lib`) runs every case's `probe.sh` under `sh` AND `bash` and requires the two to agree, because the idiom it replaces does not: `${2:?}` exits 1 under bash and 2 under dash, so `shellcheck-gate.sh` - which declares `exit 1 = findings` - reports a usage error as a FINDING under one shell and as UNKNOWN under the other. A single-shell control cannot see that, so the disagreement is its own verdict (`unknown`, exit 2) rather than folded into either answer. A probe that exits non-zero without printing `gate-lib: refused - ` is also `unknown`, not `refused` - the #946 rule, that a crash is not a detection, applied inside the instrument written for it
- gate-lib anchor is SYNTHETIC and always will be, because the module has no pre-fix version: #1061's constraint 1 requires the control to land BEFORE any caller, so there is no historical commit to vendor. What `anchors/0000000-naive-gate-lib.sh` refutes is a DESIGN - the "substitute a sensible default" module that accepts a missing value as `""`, accepts a second verdict at 0, and falls through to the good exit on an unmapped verdict. It carries a byte-equivalent `--check` runner so a verdict difference isolates the four library functions and nothing else, and it misses all four known-bad cases while agreeing on both known-good ones. Provenance reads `unverified` for that structural reason rather than the ordinary temporary one
- gate-lib qualifies #992's claim, and the qualification matters for #1127. Measured, `set -- one; shift 2`: under **bash** `shift` returns 1 and leaves the positional parameters alone, so `$#` never decreases and the loop turns on the same argument forever - the #992 hang; under **dash** `shift: can't shift that many` is FATAL and the shell exits 2 on the spot, with no hang at all. #992's six subjects are all `#!/usr/bin/env bash` and its fix stands, but the general claim does not carry to a POSIX-sh gate - and `shellcheck-gate.sh`, #1127's first migration target, is one, where the naive idiom would not spin but would die with exit 2, which that gate's own contract reads as UNKNOWN. Pinned by `tests/test_gate_lib.py::test_the_naive_loop_this_module_replaces_never_reports_the_usage_error`, which asserts the timeout under bash and the fatal exit under sh, and in both the property that survives: the loop never reaches its own result, and what it says is about the shell's `shift` builtin rather than about the flag the caller typed
- gate-lib has NO CALLER YET, deliberately (#1061 constraint 3: migrate one caller at a time, with that caller's existing tests unchanged, because a rewrite that also rewrites the tests cannot show the behaviour was preserved). #1127 migrates the four gates that already carry a registered control, and those controls are the regression evidence
