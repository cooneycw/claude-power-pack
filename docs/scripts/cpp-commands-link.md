Per-script history, indexed from [the scripts inventory](../scripts.md).

## `cpp-commands-link`

- cpp-commands-link - user-scope command-surface symlinker (#663, the canonical Tier 1): per-family links `~/.claude/commands/<family>` -> the checkout's `.claude/commands/<family>`, so the executed command text follows `git pull` atomically with no cache to reconcile (the property the retired /plugin lane lacked, #662 / ADR 0005); touches ONLY symlinks whose target ends `/.claude/commands/<family>` (owned shape) - a user's real file/dir or foreign symlink is reported and never modified; prunes owned links for families the checkout no longer ships; `--check` read-only and splits drift (#756): MISSING-only is `drift-missing` (exit 3), which `/cpp:update` Step 5c self-heals without a prompt; any STALE link (points at another checkout) or owned ORPHAN for a retired family is `drift` (exit 1) and still needs a human; STALE wins over MISSING when both are present; foreign remains not-drift; contract `CPP_COMMANDS_LINK: ok|installed|drift|drift-missing|error`; run by `/cpp:init` Tier 1 and verified by `/cpp:update` Step 5c
- cpp-commands-link `ok: 0` printed `ok` (#1138) - the install and `--check` verdicts had no word for "not one family is mine, and every name I would use is taken", so that state printed the same `CPP_COMMANDS_LINK: ok`, exit 0, as a fully-linked surface - on the same line as `families: 18 ok: 0 ... foreign: 18`. Measured in a faithful clone of a live kyle session container, 2026-09-20: all 18 families classify `foreign` there because the substrate projects the command surface as READ-ONLY BIND MOUNTS, and a bind-mounted directory is not a symlink this installer created. The ownership rule was never the defect - a foreign entry IS the user's content and their choice still wins - the defect was two states sharing one word, which is the failure an installer can least afford: a green from one that installed nothing is indistinguishable from a green from one that worked. Now `unowned` (exit 4) in BOTH modes. Both, because `--check` shared the blind spot: ADR 0008 excluded this script from its census on the grounds that an installer's state "is re-derived by the drift and parity checks", and on this input the re-derivation returned the identical wrong answer, so their agreement carried no information. The same change moved it to census row 97 and corrected `.claude/verify-coverage.json`, which classed it `not-a-checker` because "it issues no verdict" - it issues five, and `/cpp:update` Step 5b acts on one. Controlled at `controls/cpp-commands-link` with a HISTORICAL anchor (the gate at `a144b54`, provenance byte-verified against git)
- cpp-commands-link source locator names its cause (#1138) - `SELF=$(readlink -f "${BASH_SOURCE[0]}")` assumes the stable path `~/.claude/scripts/cpp-commands-link.sh` is a SYMLINK into the checkout, and line 94 said so in a comment. In a kyle container it is a BIND MOUNT, which `readlink -f` resolves to ITSELF, so `SRC` became `~/.claude/.claude/commands` - wrong rather than absent. The refusal already existed and was correct; it named the phantom path and sent the reader hunting for a directory that was never supposed to exist. It now detects the non-symlink case POSITIVELY (`[ -L ]` on the invoked path, not inferred from which wrong path happened to be missing), reports the basis on every refusal, and says to pass `--source`. A symlink and a bind mount are indistinguishable to `ls`; they resolve differently
