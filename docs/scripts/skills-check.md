# `skills-check` - script reference

Per-script history, indexed from [the scripts inventory](../scripts.md).

## `skills-check`

- skills-check - read-only skill-surface gate added for issue #720 after three independent ownership hazards became visible: a broken untracked `.claude/skills/pptx` symlink could exist only on one host, gitignored `.agents/skills/` copies could drift without any repository signal, and the generated Codex command-family skills were being mistaken for the separate Claude topic-knowledge surface. The stdlib-only scanner validates canonical `.claude/skills/<slug>/SKILL.md` metadata, provenance, local references, and duplicate surfaces, then byte-compares only `.agents/skills` packages carrying an explicit `metadata.source` link to CPP. Missing `.agents/skills` is the normal clean-checkout state; marked stale or orphaned installs fail without repair, while unmarked user-authored neighbors are ignored and never modified. Vendored and adapted provenance must name the upstream author, exact source URL, license, pinned revision, and local-change summary; CPP self-sourcing is rejected as false attribution. `make skills-check` is standalone like `codex-skills-check`, while `tests/test_skills_check.py` supplies the CI gate in the git-less validate image

- skills-check gained the three rules the surface it guards was failing, in #1034. (1) The Agent Skills spec requires `name` to be 1-64 lowercase alphanumerics and single internal hyphens AND to match the parent directory; 18 of 18 canonical packages carried a human title instead (`Code Quality`, `Python Packaging (PEP 621 & PEP 723)`), so the identifiers other agents and installers key on were all invalid and the checker built to catch exactly this had no rule for it. The current tree was the committed red case: 18 `INVALID_NAME` findings before the rename, 0 after. A shape violation returns without also reporting the directory mismatch it implies; a well-shaped name pointing at the wrong directory is reported on its own. (2) `trigger:` is not a spec field, so nothing loads it - all 18 packages stored good cue vocabulary in a key no agent reads, while `description`, the only always-loaded pointer, stated capability alone. The descriptions were rewritten to carry a triggering condition and `UNREACHABLE_TRIGGER` guards the regression. IT IS A FLOOR AND NOT A QUALITY MEASURE: one shared term satisfies it, 17 of 18 already cleared it before the rewrite, and a share-of-terms rule was rejected because keyword-stuffing the protected field satisfies it. (3) The managed-mirror comparison is opt-in through `metadata.source`, a value stored inside the file being verified, and `Report.ok` is `not findings` - so a package that loses that line is skipped with no finding, no note, and an unchanged "ok". The summary now states the skipped population, leaving the protection boundary where it is: unmarked content is still never judged, merely no longer silent. `install-drift` reports it too, since it is the note's main automated reader, and initialises the counter to `?`/null rather than 0 so a parse that never ran cannot render as a measured zero (#1029 doctrine; the 0 initialiser was caught by mutation, where deleting the parse left the assertion green). Not addressed here, and filed separately: CPP's stdlib frontmatter parser splits on the FIRST colon, so a plain scalar containing `: ` parses cleanly here and is rejected by any real YAML loader - three of the rewritten descriptions hit this and skills-check reported `ok` on all three
- skills-check `--managed-root DIR` (#1029) points the managed-install comparison at a root other than `<root>/.agents/skills`, exposing the parameter `check_repository` already took. `install-drift` uses it to cover `~/.claude/skills`; writing a second, weaker comparison in bash would have been a different instrument answering the same question, and the two would drift
