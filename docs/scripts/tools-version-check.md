# `tools-version-check` - script reference

Per-script history, indexed from [the scripts inventory](../scripts.md).

## `tools-version-check`

- tools-version-check - "present" is not "current" (#1029, specimen 3). `make tools-check` (#987) asks `command -v <tool>`, which ANY version satisfies identically, while `.woodpecker.yml` pins `koalaman/shellcheck-alpine:v0.10.0@sha256:...` and states the reason in its own words - *"running the gate under two different linters would make the control's verdict depend on which container reached it"*. So a host whose apt supplied shellcheck 0.9.0 got `tools-check: ok` and a `controls/shellcheck-gate` verdict that need not match CI's, with nothing anywhere saying the two gates ran under different instruments. Folded into `make tools-check` (one `--quiet` line after its own verdict) and available as `make tools-version-check`
- tools-version-check READS the pins, never re-declares them. A literal `0.10.0` here would be a THIRD copy of a version that already exists in two places and would go stale at the first bump - the hand-maintained-number failure #1002 removed from the ADR 0008 census. shellcheck and gitleaks come from the Makefile's `SHELLCHECK_IMAGE` / `GITLEAKS_IMAGE` image tags, jq from `ci-stage-jq.py`'s `JQ_URL` release path; `tests/test_pinned_tool_versions.py` holds the Makefile's two digests byte-identical to `.woodpecker.yml`'s, so "the pin that already exists in .woodpecker.yml" stays ONE declaration read from the convenient end rather than two that drift. Found a live mismatch on the reference host the day it landed: staged jq 1.7.1, host jq 1.7
- tools-version-check contract - per-tool `pinned`/`installed`/state lines, then `TOOLS_VERSION: ok | mismatch | absent | unknown`. Aggregate precedence is `unknown` > `mismatch` > `absent` > `ok`, and every per-tool line prints regardless so an aggregate never conceals a finding: `unknown` outranks `mismatch` because a pin that could not be parsed means the comparison DID NOT HAPPEN, and an unmade comparison must never render as a made one; `absent` ranks last because `tools-check` already reports absence loudly. It does not gate - absence and divergence are reported and the caller continues to the target that runs the tool, which is where the honest verdict lives
