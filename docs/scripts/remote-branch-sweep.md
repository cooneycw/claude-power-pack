## `remote-branch-sweep`

- remote-branch-sweep (#1262) REPORT-FIRST, AND EVERY DELETION RE-DERIVED AT THE MOMENT IT HAPPENS. The per-merge path stopped orphaning branches in #848/#852; the backlog from before it (101 remote branches besides `main` on 2026-09-28) had no owner, because deleting a remote branch can destroy the only copy of someone's work. `report` classifies every branch and deletes nothing; `plan` prints the per-branch decision; `delete` needs `--confirm` and a `--checkout`, refuses a fixture outright, re-reads each (a) branch from the live API immediately before deleting it, and deletes with `git push --force-with-lease=refs/heads/<b>:<tip>` so a racing push is not destroyed. Category (a) is master's narrowing of the operator's "do 1262" authorisation, adjusted for squash merges - never quoted as operator wording: a MERGED PR whose recorded head IS the current tip (nothing pushed after the merge) AND whose `merge_commit_sha` is reachable from the default branch (GitHub's compare API, `ahead`/`identical` with `behind_by: 0`). Literal ancestry cannot work in a squash repository - the branch's commits are rewritten onto main under new shas - which is why the tip-equals-merged-head reading exists. Everything else is reported and left alone: (b) closed unmerged, (c) never had a PR, (d) an open PR or a scanned local worktree, and excluded (default, protected, pushed within 24h, or merged but moved after the merge / merge commit off the default branch). "Pushed within 24h" takes the NEWER of GitHub's activity API and the tip's committer date and prints which answered - but the committer date alone NEVER licenses a deletion (counter-model review, replacing the orchestrator's earlier fallback): it cannot see a push, since a branch recreated today at an old merged commit keeps that commit's date, so a branch whose activity record does not answer is EXCLUDED. `delete` also verifies that the checkout's single `origin` push URL names `--repo` itself (a fork origin with the same branch and sha would otherwise pass the lease), and re-reads the default branch and rescans every checkout's worktrees per branch; a failed scan refuses, in `plan` and `delete` alike. `gh` 2.45 has no `--slurp`, so the complete listings use `--paginate --jq '.[]'` and parse one object per line. Measured before any deletion: 103 branches, a=91 b=4 c=2 d=2 excluded=4, with (a) rows verified by hand against the API
