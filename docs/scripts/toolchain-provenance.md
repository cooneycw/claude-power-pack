# `toolchain-provenance` - script reference

Per-script history, indexed from [the scripts inventory](../scripts.md).

## `toolchain-provenance`

- toolchain-provenance - report what version the EXECUTED copy of CPP actually is, as a NUMBER (#1029, specimen 1). `~/.claude/scripts/*` symlink into one shared checkout that every session on the host runs its instruments from; on 2026-09-15 that checkout was 21 commits behind `origin/main` while PR #993's merge-starvation tracking sat merged and unreachable. `git log origin/main` said the feature shipped, `<helper> --help` said the flag did not exist, and NOTHING COMPARED THE TWO - a wave-ledger conclusion ("an instrument built, merged, and never invoked") was drafted from that gap and was factually wrong, corrected only because a worker tried to comply and found the flags missing. Read-only: it never fetches, never pulls and never writes, because `flow-finish-gate.sh` resolves `CPP_DIR` to that same checkout and runs `lib.cicd` from it LIVE, so a pull mid-wave hot-swaps every instrument under every running session including the ones verifying the pull. The remedy for a live gap is a sequenced upgrade at a declared safe moment, and `checkout-readers` answers when that is
- toolchain-provenance contract - `TOOLCHAIN_PROVENANCE: current | behind | ahead | diverged | unknown`, with `behind`/`ahead` as counts and `-` wherever nothing was measured. A `0` is never printed for an unmeasurable checkout: "measured, gap zero" and "could not measure" are different answers and only one is evidence, so every unmeasurable state reports `-` and names its reason. `ahead` is a separate state rather than a flavour of `current` - a checkout carrying local commits is not stale, but it is also not what a reviewer read. The upstream compared against is the CURRENT BRANCH's own `@{upstream}`, never a hardcoded `origin/main`, or a checkout parked on a release branch would report a fabricated gap. `fetch_age_seconds` travels with the counts because `behind=0` against a three-day-old remote-tracking ref is a confident statement about three-day-old information, and reporting the gap without the age of its evidence re-creates the original failure with a number attached. Checkout resolution is SELF-FIRST: this file's own location is the one thing that cannot be wrong about which checkout is executing. Consumed by `install-drift` (every mode) and by `flow-wave-registry register`, which emits `FLOW_WAVE_TOOLCHAIN` / `_BEHIND` so a wave says it is starting on a stale toolchain at registration instead of discovering it eleven hours later
- toolchain-provenance dates HEAD as well as the fetch (#1342). The fetch age says how old the EVIDENCE about the remote is; it says nothing about the CODE being executed, and two commits behind a ten-minute-old HEAD and two behind a nine-day-old one are the same count and different situations. HEAD's committer date - a claim written into the commit, not the time this checkout moved to it, and labelled that way - is reported as `head age` in the report, `head_age_seconds` in `--json` (appended, so existing keys keep their place), `TOOLCHAIN_HEAD_AGE=` in the key contract (it does not match install-drift's `^TOOLCHAIN_HEAD=` read), and `HEAD committed Nh ago` in the quiet `behind`/`diverged` line. An unreadable date is `-`/null and `HEAD age unknown`, never a `0` that would read as fresh.
