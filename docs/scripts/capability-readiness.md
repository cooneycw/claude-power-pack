# `capability-readiness` - script reference

Per-script history, indexed from [the scripts inventory](../scripts.md).

## `capability-readiness` (#1290)

- capability-readiness - one readiness table for flow, second-opinion and browser-qa, run by `/cpp:status`. Installed is not usable: a playwright registration failed to connect (the server exits 5 before `initialize` when no browser is installed), and the reachability curl this replaced grepped `http://127.0.0.1:8080}/mcp` out of `${SECOND_OPINION_URL:-...}/mcp`, brace included, so it could never report reachable
- capability-readiness states - one per row: `disabled` (optional; never affects another row), `unexamined` (installed, the proving layer not probed - unreadable config, credentials in the endpoint, an unsupported transport), `stale-or-unknown` (checkout behind/ahead/diverged/unknown, or an installed artifact missing or stale), `conflicting` (one MCP name, 2+ scopes, different endpoints - each scope's handshake is shown and none is picked), `unreachable` (the probe ran and failed), `ready` (for the named probe ONLY; each row lists what stayed unexamined)
- capability-readiness probes - flow runs the installed `flow-driver-capability.sh list`; the MCP rows do `initialize` + `tools/list` and call no tool, so no model request is made. A stdio server launched through npx/uvx/bunx/pnpx or a package-manager exec form (`npm exec`, `pnpm dlx`, `yarn dlx`, `bun x`, `uv tool run`) is not started (`unexamined`): an offline flag does not stop npx installing from a warm cache. Other stdio servers start with `UV_OFFLINE`, `UV_NO_SYNC` and `npm_config_offline`, in their own process group under a hard timeout, killed and reaped; the HTTP handshake has one overall deadline and reads an SSE stream only until the answer. `ready` needs every scope's probe of one endpoint to succeed; a dangling install link is a broken install (`stale-or-unknown`), never `disabled`. An endpoint carrying userinfo, a query or headers is not probed (`unexamined`): an authenticated probe is not authorised for status
- capability-readiness consumes, never re-derives: `flow-helpers-install.sh --check`, `cpp-commands-link.sh --check`, `cpp-checkout-freshness.sh` (which fetches) and mcp-drift's scope reader and redaction (#1256). Endpoints are printed only through that redaction; probe failures are reported by exception TYPE, never by message
- capability-readiness contract - table by default, `--json` for the same rows (one list, no reclassification); last line `CAPABILITY_READINESS: ready | degraded | unknown`, exit 0/3/4 (2 usage). `ready` needs every enabled row ready and at least one enabled. Seams: `--home`, `--checkout`, `--project-dir`, `--timeout`. Controls: `tests/test_capability_readiness.py` (including the clean-home install/update smoke through the real installers) and `controls/capability-readiness`, whose anchor is the pre-fix status.md block
