# `codex-review-run` - script reference

Per-script history, indexed from [the scripts inventory](../scripts.md).

## `codex-review-run` (#1847)

- THE CROSS-MODEL REVIEW IS ONE HELPER CALL, NOT A DOCUMENT TO ASSEMBLE. `/codex:code_review` printed its procedure as six fenced bash blocks (3,484 of its 6,216 words, measured on `f1253b45`): collect the diff, probe the sandbox, probe the network, withdraw credentials, run codex, relay. Running it on #1846 meant extracting five of them into a scratch script, and nothing checked the result; a dropped block (the credential withdrawal, say) still produced findings. The blocks moved here unchanged, one function per stage (`review_preflight`, `review_collect_diff`, `review_run`, `review_model`, `review_relay`), and the command now calls the helper bare. The markers and the findings format are unchanged, because `counter-model-receipt.py` and `/flow:auto` Step 5 read them.
- THE STAGE TESTS STILL RUN EACH STAGE. `tests/test_code_review_*.py` used to execute each document block; they now execute each stage's body, read from this file by `review_stage()` in `tests/test_codex_review_run.py`, so their mutation cases (strip the trap, swallow the intent-to-add failure, restore the pre-fix enumeration) still apply. `tests/test_codex_review_run.py` drives the whole helper as a caller does. Sourcing the file defines the stages without running them.
- TWO DEVIATIONS FROM THE ISSUE'S PROPOSED APPROACH, both approved by the owner on #1847. The reviewer prompt stays inside `review_run` as one string, not a sibling text file: it is built byte-for-byte as before, with no placeholder substitution (a context carrying `&` would have been rewritten by bash's pattern replacement) and no second file to install. The `codex exec --json` event stream goes to the retained stream file only: copied to stdout as well, it buried the marker lines the caller reads. Red cases: `test_a_context_reaches_the_reviewer_literally`, `test_the_event_stream_is_not_on_stdout`.
- A FAILED `codex exec` IS `unavailable`, NEVER `ran`. The document told callers to treat a nonzero `CODEX_EXIT` like the exit-3 unavailable case; the helper now says so itself, as `CODEX_REVIEW: unavailable (codex exec exited N)`, exit 3, with the relay still written to the transcript. Red case: `test_a_failed_codex_exec_is_unavailable_never_ran`.
- A RECEIPT FLAG IS READ FROM THE TRANSCRIPT, NEVER CARRIED BY HAND. `/flow:auto` Step 5 1d used to pass `$STREAM`, `$CODEX_REVIEW_SCOPE` and friends, shell variables no call ever set across the command boundary. Every relay marker is one `NAME: value` line in the transcript, and 1d reads each with a one-line `sed` reader. The plan first gave the helper a `--marker NAME FILE` mode for this; it was dropped during implementation because `scripts/check-driver-parity.py` refuses a helper call inside a shell function or `$(...)` (it cannot derive membership from one), and reading the file needs no helper. An absent marker reads as nothing; for `--scope`, `--network` and `--local-credentials` the receipt writer's own `choices` then refuse the empty value. Pinned by `test_flow_autos_reader_gets_every_receipt_flag_from_a_real_transcript`; red case `test_a_marker_missing_from_the_transcript_reads_empty_never_a_default`.
- THE MERGE-BASE REFUSAL IS PINNED BY ITS REASON, NOT ITS EXIT. Found while showing each moved test red against a broken helper: with the `no common ancestor` guard removed, the later failed-diff refusal still exits 3, so every exit-code test stayed green, and the old document tests only checked the text. `test_a_base_with_no_common_ancestor_is_unavailable_by_name` asserts the named refusal and that no `codex exec` ran.
- THE TRANSCRIPT LIVES OUTSIDE THE WORK TREE, AND A FAILED WRITE IS NEVER `ran` (counter-model review of #1847, passes 1 and 2). A transcript inside the checkout is an untracked file the next run's diff stage marks intent-to-add: an enrolled repository then blocks a clean checkpoint, and any other repository reviews its own previous report as part of the change. Pass 1's fix (create it only after the review) covered the first run only; pass 2 found the second, so the approach was narrowed: a transcript path inside the work tree is refused, exit 2, before the review and without creating the file. And an unwritable or full destination still ended in `CODEX_REVIEW: ran`; the relay now runs under errexit in a subshell (deliberately not as an `if` condition, which would disable it), and any failed write is `unavailable`, exit 3. Red cases: `test_a_transcript_inside_the_work_tree_is_refused_before_the_review`, `test_a_transcript_that_cannot_be_written_is_never_ran` (`/dev/full`).
- A SYMLINKED TRANSCRIPT IS REFUSED, dangling or not (counter-model review, pass 3). The in-tree check resolves the parent directory only, so `/tmp/review.md` linked to a tracked file passed it and the relay overwrote that file. Landed after the third and last review pass on the owner's ruling, without a fourth pass. Red case: `test_a_symlinked_transcript_is_refused`.
- THE VERDICT LINE DECIDES BEFORE THE PARSE (counter-model review, pass 2). A failed `codex exec` can leave a clean-looking report, which `counter-model-receipt.py parse` reads as `clean`; `/flow:auto` 1b now parses only on `ran`. An early refusal's verdict is its `CODEX_REVIEW:` line on stderr, which a hint line may follow, so no caller reads "the last line". Red cases: `test_the_verdict_decides_before_the_parse`, `test_every_early_refusal_carries_a_verdict_line`.
- NOT COVERED: kyle derives a container's required binaries from `command -v` probes in CPP command documents (`tests/fixtures/container-surface/cpp-commands-contract.json`); the `codex` and `curl` probes now sit in this script, so a kyle re-pin would no longer see them there. Filed in kyle.

- FINDING KINDS (#1864) come from the paired receipt helper's `finding-kinds`
  verb. The prompt includes a Kind field using those alternatives. A missing,
  failing, empty or malformed kind list refuses before any reviewer call:
  `CODEX_REVIEW: blocked (finding kinds unavailable)`, exit 1. Pinned bundles
  must update both helpers together; there is no fallback vocabulary.
- HELPER RESOLUTION (#1864): `CM_RECEIPT` explicitly overrides the parser;
  otherwise it first tries `counter-model-receipt.py` beside the script's
  resolved realpath, then the installed `~/.claude/scripts` and plugin paths.
  This supports installed symlinks, copied repair installs and generated Codex bundles.
  `/flow:repair` now includes the required parser in its install family.
  CPP init/update's executable-script loops already carry both files.

- The kind lookup runs immediately before prompt execution, after the existing
  patch-size, sandbox, network and credential verdicts. An unavailable parser
  cannot replace an earlier refusal. Sibling resolution uses `readlink -f`,
  without invoking Python. `CM_PYTHON` optionally selects one interpreter
  executable (default `python3`); tests supply their own `sys.executable` for
  restricted PATHs. The same selection serves receipt-patch and model lookups.
  A failed late lookup removes its owned temporary patch and review HOME.
