## `check-doc-helper-flags`

- check-doc-helper-flags - every flag an instruction document passes a `~/.claude/scripts/` helper must appear in that helper's source (#1835). The three delegated drivers (rendered from `templates/delegated-driver-core.md`) told a worker stuck on plan approval to escalate with `flow-wave-mailbox.sh send ... --kind message`; the mailbox has no `--kind` and its parser ends in `--*) usage_fail`, so the escalation exited 2 and never sent. skillc's `dangling-reference` rule (cooneycw/skillc#725) found it from outside; nothing in CPP compared a document's flags with a helper's parser
- check-doc-helper-flags contract - scans `.claude/commands/**/*.md`, `.claude/skills/**/*.md` and `templates/**/*.md`. For each `~/.claude/scripts/<helper>` it takes the rest of the command, joined across `\` continuations, with `$(...)` substitutions removed, and reads it as shell words QUOTE-AWARE: it ends at the first unquoted `|`, `;`, `&`, backtick, word-initial `#` or next helper path, and a flag is an unquoted word starting `--`, or the unquoted `--name=` prefix of a word whose value is quoted. A helper path inside a quoted argument (an `echo` hint, a `--body` message, a variable assignment) is not an invocation and is counted on stderr as unchecked; a `$(` inside double quotes is. Counter-model review found each quoting shape across two passes; each has a control case. Exit 0 `ok - F flag(s) on I invocation(s) in D doc(s) checked`, exit 1 with one `UNKNOWN_FLAG: doc:line: helper flag` per finding, exit 2 `UNKNOWN` when no document or no resolvable invocation was examined. `--root DIR` scans another tree. Stdlib-only, offline, git-free
- check-doc-helper-flags is permissive by design: a flag is known when its literal text appears anywhere in the helper's source, comments included, or in a sibling the helper hands off to through a `$..._DIR/<name>` path (`flow-preflight.sh` runs `flow-preflight.py`). For a Python source the bare name as a quoted string also counts, because `flow-wave-completion.py` builds `--wave`, `--role` and `--assignment-id` as `'--' + name`; without that rule the first run raised 33 false findings. So it can miss a bad flag but not block a good one. It does not bind a flag to a verb, read flags written before the helper path, or check helpers outside `scripts/` (named on stderr as unchecked)
- check-doc-helper-flags is a gate that lets work THROUGH, so it carries a committed negative control (ADR 0008): `controls/doc-helper-flags` holds the #1835 shape on one line and on a continuation line (both BAD), and a GOOD tree with every shape a naive extractor misreads. The anchor is constructed: confirm each named helper exists. It misses both BAD cases
