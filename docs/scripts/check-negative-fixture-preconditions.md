## `check-negative-fixture-preconditions`

- check-negative-fixture-preconditions - gate for the "a negative-condition fixture asserts its own precondition" core directive (#697), the reflexive case of the #673/#674/#677/#685 defect class: it was found inside a test written to check exactly that class. Stdlib-only `ast` walk over `tests/`: flags a function that replaces `PATH` WHOLESALE (`env["PATH"] = str(stub)`, `os.environ[...]`, `monkeypatch.setenv`) - the statically visible way a test constructs a tool's absence - with no `shutil.which` assertion in the same function. A value DERIVED from the existing `PATH` is a prepend, adds without removing, and stays silent, as do `delenv` and outcome assertions - the three shapes #697 names safe, each pinned by its own negative fixture so the rule cannot be over-applied. Scoped to `PATH` alone and to same-function assertions, and assertion ORDER is not checked: a floor for the shape that actually failed, not proof of total coverage. `# negative-fixture: allow <reason>` is the escape. `make negative-fixture-check`, folded into `make verify`, and asserted by `tests/test_negative_fixture_preconditions.py` - whose load-bearing test MUTATES the one real instance (strips the PR #695 assertion) to prove the gate still fires, since the detectable population is one already-compliant line and a clean run alone cannot distinguish a working gate from a dead one

- codex-skill-sync SUCCESS LINES NAME THE COMPARED TREES (#1029, specimen 4). `--check` printed `N skill(s) in sync`, which is the line a session reaches for when it wants to know whether its INSTALLED skills are current - and it answers a different question, because `run_check` compares `.claude/commands/<family>/` with `codex/skills/`, BOTH INSIDE THE CHECKOUT. It is a generation-parity check, and `--check` is the DEFAULT mode, so the wrong reading was the easy one. Measured twice, four days apart on two hosts: in the same session this printed its green, `install-drift` reported `65 current, 10 stale`, and the staleness was real - the installed `flow-check/scripts/flow-finish-gate.sh` still carried pre-#939 wording, with `SKILL.md` byte-identical in all ten, so the entire drift lived in the bundled payload scripts that this comparison structurally cannot see. All three modes now name both ends and say what they did NOT look at; `--install` is the only one whose subject is the install tree. No negative control is owed for a string change - the pairing test is that the two instruments' success lines can no longer be read as answering the same question, pinned by `tests/test_codex_skill_sync.py`
